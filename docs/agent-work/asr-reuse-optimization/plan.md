# VoiceBridge 商用 ASR 复用优化计划

状态：待执行  
负责人：主 agent 统筹；后续 sub-agent 按工作包领取  
研究依据：[research.md](./research.md)  
执行记录：[progress.md](./progress.md)

## 1. 最终目标

在不破坏 VoiceBridge 现有商用底座的前提下，提高中文短句、语气词、专有名词、标点和数字格式的质量，并建立可切换、可度量、可回滚的 ASR 架构。

目标不是“换成某个开源模型”，而是通过同一批真实语料证明新方案优于当前腾讯基线后再采用。

## 2. 强制执行原则

1. **保留优先**：账号、配对、Realtime、ACK、计费额度、桌面注入、窗口选择和语音命令不迁移。
2. **复用优先级**：官方依赖/SDK → 官方服务或容器 → 小范围移植成熟模块 → 参考架构自行实现 → 完全自研。
3. **禁止盲抄**：没有量化收益、许可证不清、维护活跃度不足或会降低跨平台能力的代码不得合入。
4. **薄适配器**：外部 ASR 作为 Provider 接入，不让第三方协议扩散到录音、计费、UI 和桌面注入层。
5. **原文可追溯**：raw、provider-final、postprocessed 三层文本必须可在测试/诊断环境比较；生产日志不得记录用户正文。
6. **模式分离**：忠实模式不删除有语义语气词；清爽模式才允许去口癖、重复和自我修正。
7. **先评测后替换**：未通过相同音频盲测和回归门禁，不得把候选方案设为默认。
8. **可回滚**：所有用户可见变化必须受配置/feature flag 控制，腾讯基线在验证期保留。

## 3. 明确保留、借鉴和拒绝迁移的范围

### 保留现有 VoiceBridge

- Supabase Auth、设备配对、private Realtime、ACK 与套餐/用量逻辑。
- Electron/CLI 桌面 Agent、剪贴板、自动粘贴、窗口激活和按键协议。
- PWA UI、命令库、文本编辑与收藏体验。
- 腾讯 Flash → Sentence 回退、请求签名和总超时预算，直到候选方案正式胜出。
- 现有 WAV 编码和测试作为回归基线；替换录音器时必须证明行为更好。

### 借鉴或复用

- `vad-web`：浏览器 AudioWorklet、Silero VAD、16 kHz speech segment 和首尾保护。
- FunASR Runtime：官方服务、模型组合、两遍识别和 WebSocket/OpenAI 风格接口。
- sherpa-onnx：本地 Node addon、模型加载、VAD/ASR/ITN/标点示例。
- Koe：TranscriptAggregator 状态契约、interim history、词典双用途和受约束 LLM 纠错。
- Type4Me：Provider 注册、状态机、热词与确定性映射、快速/润色模式。

### 不整体迁移

- 不迁移 Type4Me 的 Swift/macOS UI 和系统注入层。
- 不迁移 Koe 的 Objective-C/Rust 产品壳。
- 不用 WhisperLiveKit 替换现有产品后端；先作为模型试验网关。
- 不把低维护度第三方 `funasr-server` 作为生产核心。
- 不因“本地模型免费”而默认把 200 MB～2 GB 模型塞入当前安装包。

## 4. 成功指标与评测集

在任何功能代码实施前，建立一套经过授权、去标识化的固定语料。建议至少 150 条：

- 30 条 0.2～1.0 秒短回答：嗯、啊、哦、对、好、可以、不是、等一下。
- 25 条句首/句中/句尾语气词与自我修正。
- 25 条产品名、人名、英文缩写和中英混说。
- 20 条数字、日期、时间、金额、百分比、版本号、邮箱和 URL。
- 20 条语音命令及与普通句子的冲突样本。
- 15 条较长自然口述。
- 15 条不同噪声、距离、语速和口音样本。

每个候选方案必须报告：

- 字符错误率 CER，以及短句完全正确率。
- 首字/尾字丢失率。
- 专有名词准确率和热词收益。
- ITN 准确率、标点边界 F1。
- 忠实模式的语义保留错误数。
- 清爽模式的误删、漏删和改义错误数。
- 空结果率、失败率。
- 端到端 P50/P95 延迟、资源占用、单分钟成本。

硬门禁：候选方案若不能在目标短句集上显著优于腾讯基线，或使 P95 延迟/失败率明显恶化，则不进入生产集成。

## 5. 分阶段工作包

后续 sub-agent 必须领取边界清晰的工作包；同一文件同一时间只允许一个写入者。每个工作包单独提交报告和验证证据，不得顺手重构无关代码。

### WP-0：第三方商用合规清单（阻断门禁）

范围：只写 `docs/agent-work/asr-reuse-optimization/third-party-review.md`，不改代码。

任务：

- 对 vad-web、Silero VAD、ONNX Runtime Web、FunASR 框架、选定模型、sherpa-onnx、选定 ONNX 模型、WhisperLiveKit 建立制品级清单。
- 记录仓库 URL、commit/tag、下载 URL、SHA-256、源码许可证、模型许可证、NOTICE/署名、再分发和商用限制。
- 核实 Docker 镜像是否允许生产使用和再分发，不仅看 GitHub 仓库许可证。
- 标记需要律师或供应商书面确认的条目。

验收：所有试验候选均为 `approved-for-evaluation`；任何许可证不清制品不得进入后续打包或部署。

### WP-1：基准语料与可重复评测工具

范围：新增独立 `test/asr-eval/` 或遵循仓库现有测试布局；不改生产路径。

任务：

- 定义 manifest 格式：音频 ID、期望忠实文本、期望清爽文本、标签、授权状态。
- 实现 Provider 输出适配、CER/短句完全正确率/首尾丢字/延迟统计。
- 输出机器可读 JSON 和简短 Markdown 报告。
- 音频文件默认不入 Git；仓库只保留合成或明确可再分发的小样本。

复用：优先使用现有 Node 测试工具和标准库；没有必要不新增大型评测框架。

验收：同一 manifest 可重复跑当前腾讯、候选 HTTP Provider 和本地 Provider；失败时命令返回非零。

### WP-2：腾讯基线拆分与低成本优化

依赖：WP-1。

任务：

- 保留当前默认行为，增加仅用于评测的参数组合：`FilterModal=0/1/2`、应用层 filler 清理开/关、热词开/关、可用的时间戳/分段信息。
- 将 raw Tencent text 与应用后处理结果分开，以证明问题属于录音、ASR 还是正则。
- 评测腾讯当前 `16k_zh`、账号实际可用的新引擎和热词能力。
- 禁止在没有数据前删除回退、deadline 或现有错误处理。

验收：产出基线报告；明确“双重语气词过滤”是否应移除或只在清爽模式启用。

### WP-3：浏览器录音/VAD 复用试验

依赖：WP-0、WP-1。

首选方案：把 `@ricky0123/vad-web` 当依赖使用；不得复制其 ONNX/AudioWorklet 实现后自行维护。

任务：

- 在隔离 adapter 中对接现有开始/停止 UI，输出仍为现有 16 kHz WAV 合约。
- 验证 iOS Safari、Android Chrome、桌面 Safari/Chrome 的麦克风权限、首字、尾字和极短句。
- 对比现有 `ScriptProcessorNode`，不要因为 API 更新而默认替换。
- 如果按住说话模式不需要自动端点，仍评估其重采样/AudioWorklet 能否独立复用。

验收：短句首尾丢字率显著下降或资源/稳定性有明确收益才替换；否则保留现有录音器，只移植必要的尾部 flush/padding 思路。

### WP-4：ASR Provider 薄接口

依赖：WP-1；不得同时与 WP-2 修改相同文件。

任务：

- 定义稳定结果契约，至少包含 `provider`、`rawText`、`finalText`、`segments?`、`words?`、`latencyMs`，不泄漏供应商字段。
- 云端 Provider 保持在服务端，密钥永不进入 PWA/Electron。
- LAN Provider 保留 Node 入口；共享的是契约和测试 fixtures，不强行共享运行时实现。
- 把腾讯包装为第一个 Provider，行为保持一致。

验收：腾讯回归测试全通过；新增 fake Provider contract tests；UI、计费和桌面协议不感知腾讯专有字段。

### WP-5：FunASR 官方服务试验

依赖：WP-0、WP-1、WP-4。

首选方案：原样部署官方 FunASR Runtime/OpenAI-compatible API 或官方容器，VoiceBridge 只写薄适配器。禁止复制模型推理代码到 Edge Function。

候选组合：

- Paraformer 中文 + FSMN-VAD + CT-Punc + ITN + 热词。
- SenseVoiceSmall + FSMN-VAD + `use_itn`，不得盲目叠加会破坏标签的标点模型。
- Fun-ASR-Nano 只作为独立候选，不与不兼容的外部 VAD/punc pipeline 强行组合。

任务：

- 固定官方版本、模型版本和容器/模型哈希。
- 用相同音频离线跑基准；需要时再验证两遍 WebSocket。
- 记录 CPU/GPU 内存、启动时间、并发、P95 和单位成本。
- 加健康检查、超时、认证和熔断设计；试验期不替代腾讯默认。

验收：形成腾讯 vs FunASR 盲测报告。没有明显净收益则停止，不因已经部署而继续集成。

### WP-6：结果聚合、词典与后处理模式

依赖：WP-2、WP-4；若做流式则依赖 WP-5。

复用策略：参考 Koe `TranscriptAggregator` 和 Type4Me 的词典/模式设计；只有可独立移植且测试充分的小模块才复制，并保留许可证。跨 Rust/Swift 到 JS 的机械重写若不比小型适配器简单，则只借契约不移植源码。

任务：

- 定义 `Interim → Definite → Final` 状态，不把临时文本直接粘贴到目标应用。
- 用户词典同时用于 Provider 热词、确定性映射和可选 LLM 上下文。
- 增加“忠实”与“清爽”模式：忠实仅做安全 ITN/标点；清爽可去口癖和重复。
- 单字/极短回答默认绕过生成式 LLM，避免“嗯”变空或被扩写。
- LLM 后处理必须温度为 0、只输出结果、禁止添加事实，并允许查看/恢复原文。

验收：固定 fixtures 覆盖“嗯，可以”“嗯”“啊？”“哼唱”“啧啧称奇”、重复、自我修正、专有名词和数字；忠实模式不得改变语义。

### WP-7：灰度、可观测性和商用发布

依赖：WP-2～WP-6 中实际被采纳的部分。

任务：

- Provider 和后处理模式使用服务器端 feature flag；支持按用户/比例灰度和立即回滚。
- 只记录 provider、耗时、字符数、错误码、模式和匿名质量反馈，不记录正文或音频。
- 更新成本模型、套餐额度、隐私政策、第三方清单和故障降级策略。
- 默认 Provider 变更必须经过真实用户小流量验证。

验收：腾讯回滚路径演练成功；无文本内容的指标可区分录音、ASR、后处理和发送阶段故障。

### WP-8：可选本地 sherpa-onnx 模式

依赖：云端主链路完成且 WP-0 许可通过。低于 WP-0～WP-7 的优先级。

首选方案：复用 sherpa-onnx 官方 Node addon 和示例，不自行实现 ONNX 推理。

任务：

- 首轮只支持一个经评测胜出的中文/中英模型。
- 模型按需下载并校验哈希，不塞入基础安装包。
- 推理放 worker/子进程，禁止阻塞 Electron 主进程。
- 明确磁盘、内存、CPU、平台 ABI 和更新策略。

验收：安装包基础体积不显著增加；模型下载可暂停/重试/删除；无网络模式通过相同评测子集。

## 6. 推荐执行顺序

```text
WP-0 商用许可 ─┬─> WP-3 录音/VAD试验
               └─> WP-5 FunASR试验

WP-1 评测工具 ─┬─> WP-2 腾讯基线优化
               ├─> WP-3 录音/VAD试验
               └─> WP-5 FunASR试验

WP-2 + WP-4 + WP-5结果
        └─> 选择保留腾讯、混合或切换
              └─> WP-6 后处理
                    └─> WP-7 灰度发布
                          └─> WP-8 可选本地模式
```

允许并行：WP-0 与 WP-1；门禁通过后 WP-2 与 WP-3。  
禁止并行写冲突：WP-2 与 WP-4 不得同时改腾讯/Provider 文件；WP-5 不得自行改 UI、计费或桌面 Agent。

## 7. 每个 sub-agent 的交付格式

每个工作包必须在最终消息和 `progress.md` 中记录：

1. 使用或复制了哪个上游仓库、精确 commit/tag、文件和许可证。
2. 为什么复用优于现有实现；若没有优势，明确建议“不合入”。
3. 改动范围和未改范围。
4. 执行过的精确命令、测试、基准设备和结果。
5. 剩余风险、回滚方法和下一工作包的输入。
6. 最终 diff 审查结果；不得提交生成模型、秘密、用户音频或无关格式化。

## 8. Definition of Done

本计划完成需同时满足：

- 至少腾讯当前配置和一个开源中文候选使用同一语料完成可重复盲测。
- 被采纳第三方代码/模型的商业许可证、NOTICE、版本和哈希完整记录。
- 中文短句和语气词指标达到预设门禁，且 P95、失败率和成本可接受。
- 忠实模式无已知改义；清爽模式可关闭、可恢复原文。
- 所有现有测试与新增评测/契约测试通过。
- 灰度和回滚已演练；隐私政策与第三方清单完成更新。
- 未被证明优于现有实现的外部模块不合入。
